# 팀원 2 — 예약·테스트 결제·반납

## 범위와 실행

작업 브랜치: `feat/team2-rental-lifecycle` (이슈·PR을 만들 때 이슈 번호를 붙입니다.)
정책 기준: `docs/confirmed-rules.md` 1.1, 구현 안내서 팀원 2의 ④⑤⑥⑧⑨⑩.
실제 카드 승인·청구·이체가 없는 테스트 금전 장부입니다.

Windows PowerShell에서 저장소 루트 기준:

```powershell
python -m venv backend/.venv-team2
backend/.venv-team2/Scripts/python.exe -m pip install -r backend/requirements-lifecycle.txt
backend/.venv-team2/Scripts/python.exe backend/lifecycle_server.py --port 8003
```

`http://localhost:8003`에서 확인합니다. `python -m http.server`에는 거래 API가 없어 새 예약을 만들지 않습니다.
로컬 서버는 127.0.0.1에만 연결하며 역할 전환 시연용입니다. 로그인·사용자 격리를 제공하는 운영 서버로 배포하면 안 됩니다.
데이터는 `backend/.rento-data/team2.sqlite`에 보관하며 Git에서 제외합니다.
다른 포트의 localStorage 데이터는 자동 가져오거나 삭제하지 않습니다. 사진 원본은 기존처럼 해당 브라우저 IndexedDB를 사용합니다.
로컬 전용 서버에는 AI·사진 분석 API가 없습니다. 분석 실패는 반납 요청을 없애지 않습니다.

## 구현된 흐름

- 예약 시작·반납 날짜와 시각을 입력합니다. 입력은 현재 기기의 시각이며 ISO 시각으로 서버에 보냅니다.
- 기본 대여료는 `ceil((endAt-startAt)/24시간) × 거래 당시 일일 대여료`입니다.
- 신청 12시간 무응답 → 신청 만료. 공급자 승인 → 1시간 결제 대기와 일정 확보.
- 실제 청구 없는 성공/실패 선택을 제공하고 성공 시에만 예약을 확정합니다.
- 승인·결제·연장 결제 때 서버가 중복 일정을 다시 확인합니다. SQLite는 BEGIN IMMEDIATE, Firestore는 공용 revision 문서의 트랜잭션으로 경쟁 요청을 직렬화합니다.
- 인도 전 취소는 결제한 대여료·보증금을 전액 테스트 환불합니다. 수령 확인 후에는 취소할 수 없습니다.
- 노쇼는 약속 시각 30분 경과, 장소, 연락 시도, 시간 변경 합의 없음 확인을 받습니다. 로컬 시연 관리자의 확정 후 전액 환불하며 기각도 가능합니다.
- 반납 촬영 완료 시 최초 요청 시각을 보존합니다. 재촬영으로 기한을 다시 시작하지 않습니다.
- 공급자 확인 또는 반납 시각 이의 없는 24시간 경과 시 완료합니다. 손상 신고가 있더라도 기본 대여료는 정산하고 보증금 반환만 보류합니다.
- 연체료는 거래에 저장한 시간대의 실제 반납일과 반납 예정일의 날짜 차이를 사용합니다. 공급자가 늦게 확인해도 연체일을 늘리지 않습니다.
- 연장은 공급자 승인과 추가 테스트 결제가 모두 완료된 후에만 적용합니다. 승인된 추가 일정도 임시 확보하고 기존 반납 기한을 넘기면 해제합니다.
- 손상·금액 이의·연체 미결제·배상 부족분 미결제는 보증금 보류 사유로 구분합니다.
- 배상 제안은 증빙 수리비 또는 거래 당시 중고 가액 상한을 확인합니다. 대여자가 제안 ID와 금액·보증금 사용에 명시적으로 동의해야 합니다. 부족분은 별도 테스트 결제를 받으며, 거부는 미해결 상태로 남깁니다.
- 결제·환불·정산 이벤트는 종류별로 구분하며 같은 요청 재시도와 중복 완료에서 중복 장부를 생성하지 않습니다.
- 서버 타이머는 15초마다 만료·자동 완료를 검사합니다. 서버 재시작 후 첫 조회/명령에서도 저장된 시각으로 복구합니다.
- 상태가 바뀐 경우 기존 거래 당사자에게 알림을 남깁니다. 변경 없는 조회는 사용자가 열어 둔 화면을 다시 그리지 않습니다.

## 서버와 다른 담당자의 연결

`rental_lifecycle.execute(records, items, actor, action, data, request_id, now, admin=False)`는
호출자가 읽고 있는 트랜잭션 스냅샷에서 명령을 처리합니다. 실패 시 호출자는 전체 변경을 롤백해야 합니다.
`advance(records, now)`는 서버 시각으로 자동 처리를 복구합니다. 테스트는 now를 바꾸며 실제로 12/24시간을 기다리지 않습니다.

`POST /api/rental-lifecycle`:

```json
{"action":"pay","requestId":"unique-client-request-id","data":{"rentalId":"r-...","outcome":"success"}}
```

로컬/기존 팀 시연은 `X-Rento-Demo-Actor`, 계정 모드는 세션과 `X-Rento-Account`를 사용합니다.
명령에는 클라이언트 금액·상태·원장·만료 시각을 받지 않습니다. 정산 필드는 일반 DB 저장 API로 변경할 수 없습니다.
새 거래 생성은 명령 API만 사용합니다. 과거 날짜 전용 거래는 결제 증거와 시각을 추정하지 않고 새 서버에서 조회 전용으로 둡니다.

| 연결 담당 | 데이터/명령 |
| --- | --- |
| 팀원 1 물품 | `price`, `deposit`, `usedValue`, `owner`, `availableFrom`, `availableTo`. 거래 시점 값을 동결하며 비율 정책을 추가하지 않습니다. |
| 성진욱 사진 | `inspection`의 plan/before/after/checks와 원본 capture 참조. handoff/return/reshoot 명령을 사용합니다. 비교 성공은 반납의 전제 조건이 아닙니다. |
| 성진욱 분쟁 | dispute, propose_compensation 및 evidence/basis/amount. 제안은 합의를 대신하지 않으며 실제 증빙 판독·금액 확인 UI는 해당 담당 범위입니다. |
| 팀원 3 후기 | `status=complete`, `completedAt`, `renterId`, `lenderId`. 후기 공개·집계는 수정하지 않습니다. |

주요 거래 필드: `lifecycleVersion=1`, `startAt/endAt`(UTC epoch ms), `timeZone`,
`requestExpiresAt`, `paymentDueAt`, `firstReturnRequestedAt`, `returnConfirmedAt`,
`actualReturnedAt`, `completedAt`, `finance`, `ledger`, `receipts`.
반납 시각 이의 검토 결과는 `resolvedReturnedAt`에 따로 저장해 최초 요청 시각을 덮어쓰지 않습니다.

## 기존 Firestore 연결

기존 compare_server의 Firestore 설정을 유지하면 동일한 명령 API와 자동 처리 작업이 연결됩니다.
기존 권한 경계는 확대하지 않았습니다. 일반 계정에 전체 거래 조회 권한을 추가하지 않습니다.
실제 계정 관리자용 전체 신고 목록/검토 UI 연결은 담당자 및 별도 권한 승인이 필요하며 이번 작업에서는 제공하지 않습니다.
Firestore 에뮬레이터/실제 프로젝트의 동시 요청·재시작 검증은 별도로 수행해야 합니다.
Cloud Run 등 유휴 시 CPU가 중지되는 배포에서 15초 스레드의 실행을 보장하지 않습니다. 지속 실행 worker/스케줄러를 운영 담당자가 연결해야 하며 조회·명령 시 복구도 함께 유지합니다.

## 미정 정책 처리

- 예약 수수료 적용 여부와 요율을 만들거나 무료 확정으로 표시하지 않습니다.
- 보증금 비율·최소·최대 금액을 만들지 않습니다. 제공된 물품의 보증금 스냅샷만 사용합니다.
- 공통 날짜 계산 시간대는 미정이므로 거래 양식에 선택한 시간대를 표시·저장합니다. 이것을 서비스 공통 정책으로 간주하지 않습니다.
- 시작 시각이 지난 신청의 승인·결제는 차단합니다. 시작 전 12시간/1시간을 확보할 수 없는 경우의 별도 정책은 확정하지 않았습니다.
- 연장 결제는 현재 반납 기한 안에서만 가능하게 하며 별도의 미확정 연장 결제 유예 시간을 만들지 않습니다.
- 실계정 권한 확대, 촬영 원본의 서버 업로드, 외부 결제, 배상 책임의 자동 판정은 포함하지 않습니다.

## 검증

```powershell
backend/.venv-team2/Scripts/python.exe -m unittest discover -s backend -p test_rental_lifecycle.py -v
cd frontend
npm ci
npm test
```

18개 서버 테스트: 시각/24시간 과금, 12시간/1시간 경계, 실패·재시도·중복 명령,
동시 승인, 재시작 복구, 직접 금액 위조 차단, 전액 환불, 반납·연체·자동 완료·보류,
연장, 노쇼, 배상 동의/부족분, HTTP 출처·역할 제한.
프런트 28개: 기존 촬영·사진 보관·등록 회귀 22개와 시각 보존·결제 UI·보류 표현·요청 ID 재사용·배상 동의 6개.
브라우저에서 26시간 신청 → 공급자 승인 → 결제 대기 → 실패 → 성공 → 예약 확정 흐름을 확인했습니다.
실제 모바일 촬영부터 반납·정산까지의 전 과정과 실계정 Firestore 검증은 완료한 것으로 표시하지 않습니다.

## 결제 안내·이의 내역 화면

- 결제 실패 시 안내창을 표시하고 결제 대기 상태를 유지합니다.
- 거래 상세와 관리자 검토창에서 이의 내용을 확인하며, 검토 완료 후 접수 내용과 결과를 기록으로 보존합니다.
- 이의 상태 카드, 지난 검토 접기, 간결한 결제·환불 기록을 제공합니다.
- 최종 검증: 프런트 28개, 서버 거래 18개 통과. Firestore 통합 테스트는 로컬 실행 환경에 Flask와 에뮬레이터가 없어 미검증입니다.
