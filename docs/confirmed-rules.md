# AI 물품대여 플랫폼 확정 규칙

- 문서 버전: 1.3
- 정리 기준일: 2026-11-28
- 목적: 채팅에서 결정한 서비스·운영·화면 규칙을 팀과 개발 AI가 함께 참고할 수 있도록 기록한다.
- 문서 상태: 정책 결정 기록. 문서에 있는 기능의 구현 완료나 검증 완료를 의미하지 않는다.

## 1. 문서 적용 기준

1. 사용자가 선택하거나 명시한 결정을 기준으로 작성한다. 기존 코드, 화면 예시, 제안서에 있다는 이유만으로 확정한 정책으로 취급하지 않는다.
2. 같은 항목을 나중에 변경한 경우에는 마지막 결정을 적용한다. 특히 연체료는 최종 선택인 **달력 날짜 기준**을 적용한다.
3. 보류·미정 항목에는 임의의 기본값을 넣지 않는다. 예약 수수료는 별도 결정 전까지 확정한 값이 없다.
4. 이 문서의 결정을 수정할 때에는 해당 규칙과 변경 이력을 함께 갱신한다.

## 2. 서비스 범위와 기본 이용

| ID | 확정 규칙 |
| --- | --- |
| SVC-01 | 개인 간 물품 대여를 지원한다. 캠핑 장비에 한정하지 않으며, 공구·디지털기기·생활용품 등 다양한 물품을 대상으로 한다. |
| SVC-02 | 여러 물품을 빌려주는 기능은 기본 이용자도 사용할 수 있다. 여러 물품을 공급할 수 있다는 사실 자체를 구독 전용 혜택으로 제한하지 않는다. |
| SVC-03 | 추천·등록 지원·대여료 추천·상태 비교 등의 역할을 플랫폼 안에서 구분하여 제공한다. 역할이 다르다고 반드시 서로 다른 AI 모델을 사용해야 하는 것은 아니며, 최종 모델 구성은 별도로 검증한다. |

## 3. 물품 등록과 사진 촬영 화면

| ID | 확정 규칙 |
| --- | --- |
| REG-01 | 물품 등록은 **기본 정보 → 사진 촬영 → 대여 조건**의 3단계로 구성한다. |
| REG-02 | 물품 등록 시 한 장의 사진만 받는 방식 대신, 품목에 필요한 여러 방향·부위의 사진을 촬영하도록 한다. 구체적인 점검 방식은 5장을 따른다. |
| REG-03 | **상태 점검 사진**은 등록 중 앱 카메라로 직접 촬영한다. **게시글 소개 사진**은 앨범 사진도 허용하며 상태 증빙·AI 비교에는 사용하지 않는다. |
| REG-04 | 상태 점검 사진은 촬영 원본을 보관하고 사용자 편집 기능을 제공하지 않는다. 소개용 앨범 사진과 상태 점검 사진은 별도로 관리한다. |
| REG-05 | 필요한 부위를 촬영하면 다음 부위로 자동 이동한다. 모든 필수 부위를 촬영한 뒤 전체 사진을 확인하며, 마지막 확인 단계에서 재촬영할 수 있다. |
| REG-06 | 사진 등록 화면은 촬영 행동과 진행 상태를 쉽게 이해할 수 있도록 구성한다. 기본 파일 선택 버튼 대신 서비스 디자인에 맞는 촬영 UI를 사용한다. |
| REG-07 | 화면은 흰색과 초록색을 중심으로 구성하고, 모바일에서 글씨가 지나치게 크거나 설명이 과도하게 밀집되지 않도록 한다. 사진 등록 디자인은 똑독 앱의 등록 화면을 참고한다. |
| REG-09 | 게시자는 **1단계 기본 정보**에서 앨범 소개 사진을 자유롭게 추가하고 공개 사진·대표 사진을 선택한다. **2단계는 상태 점검용 필수 부위 촬영**으로 구성한다. 물품 상세의 **전체 상태 사진 보기**에서 공개 사진 선택과 무관하게 모든 필수 부위의 등록 사진·촬영일을 확인할 수 있다. |
| REG-08 | 사진 촬영이 미완료여도 대여 조건 단계로 이동할 수 있다. 미완료 사진 단계에는 완료 체크를 표시하지 않는다. 최종 게시를 시도하면 사진 촬영이 미완료임을 안내하고 게시를 차단한다. 안내에서 사진 촬영 단계로 이동할 수 있으며 입력한 대여 조건은 유지한다. |

## 4. 거래 과정의 상태 사진과 비교

### 4.1 진입 위치와 촬영 원칙

| ID | 확정 규칙 |
| --- | --- |
| PHO-01 | 대여 전후 사진 비교는 독립적인 일반 메뉴보다 **대여 과정에 포함된 기능**으로 제공한다. |
| PHO-02 | **대여 내역 → 내 대여 → 물품 카드 → 거래 상세**에서 해당 거래의 전후 사진과 비교 결과를 확인할 수 있도록 한다. 내 정보의 독립 사진 비교 메뉴는 제거한다. |
| PHO-03 | 등록 때 모든 필수 면을 앱에서 촬영한다. 인도 때는 등록 사진과 실물을 양측이 확인하고 **변경된 부위만 앱에서 재촬영**한다. 재사용 사진의 실제 촬영일은 유지하며 등록 사진과 인도 직전 재촬영 사진을 구분한다. 반납 사진은 앱에서 직접 촬영한다. 소개용 앨범 사진은 거래 상태 사진으로 사용하지 않는다. |
| PHO-04 | 촬영 원본은 편집하지 않고 보관한다. 정렬·크기 조정·분석용 변환과 결과 표시에는 원본과 구분되는 사본을 사용한다. |
| PHO-05 | 사진 비교 대상 품목은 품목별로 필요한 여러 면·부위를 촬영한다. 한 면만 촬영한 결과로 물품 전체의 상태를 확인했다고 표시하지 않는다. |
| PHO-14 | 공급자는 인도 전 모든 부위·구성품의 현재 상태를 확인한다. 대여자도 각 부위·구성품을 확인한 뒤 수령을 확정한다. 확인되지 않은 상태에서는 대여가 시작되지 않는다. 상태가 다르면 수령 전 공급자가 해당 부위를 재촬영·수정하며, 수령 확정 이후 인도 사진은 변경할 수 없다. |
| PHO-06 | 촬영 대상 면·부위가 가려지거나 잘리지 않도록 안내한다. 흐림·조명·각도 때문에 상태를 확인하기 어렵다면 재촬영을 안내한다. |

### 4.2 반투명 가이드와 분석 순서

| ID | 확정 규칙 |
| --- | --- |
| PHO-07 | 반납 촬영 시 **같은 부위의 대여 전 사진을 반투명 가이드**로 보여주어 구도와 방향을 맞추도록 돕는다. |
| PHO-08 | 반투명 가이드는 촬영을 돕는 화면 표시이며, 가이드가 합성된 화면을 촬영 원본 대신 저장하지 않는다. |
| PHO-09 | 손상 분석 전에 촬영 대상 면이 선명하고 비교 가능한지 품질을 확인한다. 품질이 불충분하면 손상 여부를 판단하는 단계로 넘기지 않는다. |
| PHO-10 | 손상 분석 전에 전후 사진이 **같은 면·부위인지** 확인한다. 다른 면이거나 동일 면 여부가 불확실하면 손상 분석을 보류한다. |
| PHO-11 | 품질과 동일 면 확인을 통과한 사진을 대상으로 위치·각도 차이를 보정한 뒤 손상 후보를 비교한다. 정렬의 신뢰도가 부족하면 무리하게 결과를 확정하지 않는다. |
| PHO-12 | 비교는 같은 면끼리 수행한다. 조명·그림자·시점 차이 자체를 신규 손상으로 단정하지 않는다. |
| PHO-13 | 비교가 어렵더라도 **반납 요청을 유지**한다. 해당 부위 재촬영 또는 공급자의 직접 확인으로 진행할 수 있도록 한다. |

분석 흐름은 다음과 같다.

```text
앱 카메라로 부위별 즉시 촬영
→ 사진 품질 검사
→ 동일 면·부위 확인
→ 위치·각도 정렬 및 비교 가능 여부 확인
→ 손상 후보 표시
→ 당사자 확인 또는 필요한 경우 관리자 검토
```

### 4.3 결과 표현과 적용 한계

| ID | 확정 규칙 |
| --- | --- |
| PHO-14 | 사용자 화면에는 전후 사진과 확인이 필요한 부위를 이해하기 쉽게 보여준다. 모델명·실험 설정·평가 지표처럼 개발용인 정보는 일반 서비스 화면에서 제외한다. |
| PHO-15 | AI가 표시한 차이는 **손상 후보·확인 참고 자료**로 사용한다. AI 결과만으로 손상 책임이나 배상액을 확정하지 않는다. |
| PHO-16 | 오류가 없어야 한다는 요구는 사진 비교의 품질 목표이다. 현재 기술로 오류가 전혀 없음을 보장하거나, 비교 실패를 정상·무손상 판정으로 바꾸지 않는다. 불확실한 경우에는 비교 보류와 사람의 확인을 제공한다. |

**구현·검증상 주의:** 앱 카메라만 허용하는 UI는 기존 파일 선택을 막기 위한 절차이다. 이것만으로 가상 카메라, 화면 재촬영, 클라이언트 조작까지 방지했다고 주장해서는 안 된다. 원본성과 촬영 경위를 어느 수준까지 확인할지는 실제 검증 범위와 함께 설명해야 한다.

## 5. 품목별 점검 방식

| 구분 | 적용 규칙 |
| --- | --- |
| 외관 비교가 가능한 물품 | 필요한 면·주요 사용 부위를 나누어 촬영하고, 같은 부위끼리 비교한다. 외관 사진으로 확인할 수 있는 손상 범위에 한하여 결과를 제공한다. |
| 드릴처럼 입체적인 물품 | 물품 전체를 하나의 평면으로 취급하지 않는다. 품목의 면·주요 부위를 나누어 촬영·확인하며, 비교 가능한 대응 부위에 한하여 분석한다. |
| 텐트처럼 펼치거나 조립해야 내부 상태를 확인할 수 있는 물품 | 보관 가방 사진만으로 본체 전체의 무손상을 판정하지 않는다. 설치·해체에 따른 촬영 부담도 고려하여 구성품·직접 점검 중심으로 구분한다. |
| 구성품이 많거나 사진 비교가 현실적으로 번거로운 물품 | 자동 사진 비교를 일괄 강제하지 않고, 구성품 및 상태 확인 항목을 사용하는 점검 방식으로 구분한다. |
| 외관만으로 확인할 수 없는 작동·성능 | 외관 비교 결과로 정상 작동까지 보장하지 않는다. 해당 품목의 직접 확인이 필요하다. |

품목별 필수 촬영 면의 정확한 개수, 구성품 목록과 작동 점검 항목은 별도 목록으로 관리해야 한다. 기존 코드의 예시 개수나 사진 최대 8장 같은 임시 제한을 사용자가 확정한 공통 정책으로 취급하지 않는다.

## 6. 대여 신청·승인·예약 확정

| ID | 확정 규칙 |
| --- | --- |
| RSV-01 | 예약 확정 순서는 **대여 신청 → 공급자 승인 → 대여료·보증금 결제 → 예약 확정**으로 한다. 공급자 승인만으로 예약이 최종 확정된 것으로 처리하지 않는다. |
| RSV-02 | 공급자가 대여 신청에 응답하지 않으면 **신청 후 12시간**에 자동 만료한다. 결제 전 신청이므로 금액을 청구하지 않는다. |
| RSV-03 | 공급자 승인 후 결제 기한은 **1시간**으로 한다. |
| RSV-04 | 결제 대기 중에는 승인된 대여 일정을 임시 확보한다. 기한 내 결제하지 않으면 승인을 만료하고 해당 일정을 해제한다. |
| RSV-05 | 예약 시 대여 시작과 반납 예정의 날짜·시각을 정한다. 기본 대여료와 반납 지연 판단에 사용할 수 있어야 한다. |

## 7. 결제와 기본 대여료

| ID | 확정 규칙 |
| --- | --- |
| PAY-01 | 이번 프로젝트에서는 **실제 청구가 없는 테스트 결제**로 결제·환불·정산 흐름을 구현한다. 실제 금액의 청구·이체를 완료한 서비스로 표현하지 않는다. |
| PAY-02 | 대여자는 공급자 승인 후 대여료와 보증금을 결제한다. |
| PAY-03 | 기본 대여료의 1일은 **대여 시작 시각부터 24시간**으로 계산한다. 남는 시간은 1일로 올린다. |
| PAY-04 | 정상 반납은 공급자 반납 확인 후 기본 대여료를 정산하고 보증금을 반환한다. 자동 반납 완료는 10장을 따른다. |
| PAY-05 | 손상 신고로 보류하는 금액은 보증금 반환이다. 기본 대여료와 보증금의 처리 상태를 구분한다. |
| PAY-06 | 예약 수수료를 적용할지 여부, 부담 주체와 요율은 보류한다. 수수료 없음 또는 특정 수수료율을 확정한 것으로 기록하지 않는다. |

기본 대여료 계산 기준:

```text
기본 과금 일수 = 올림((예약 종료 시각 - 예약 시작 시각) / 24시간)
기본 대여료 = 일일 대여료 × 기본 과금 일수
```

- 예약 기간이 24시간이면 1일분, 26시간이면 2일분이다.
- 이 기준은 기본 대여료의 계산 단위이다. 연체료 계산에는 11장의 달력 날짜 기준을 적용한다.

## 8. 보증금과 물품 가액

| ID | 확정 규칙 |
| --- | --- |
| DEP-01 | 보증금은 공급자가 금액을 임의로 정하는 방식 대신, **물품 가액의 일정 비율을 플랫폼이 계산**하는 방식으로 한다. |
| DEP-02 | 기준 물품 가액은 **공급자가 입력한 현재 중고 가액**으로 하며 근거 자료를 확인한다. |
| DEP-03 | 손상·분실 배상 상한에 사용할 중고 가액은 거래 당시 확정한 값을 기준으로 한다. |
| DEP-04 | 시연 보증금은 **현재 중고 가액의 30%**를 원 단위로 반올림한 뒤 **최대 200,000원**을 적용한다. 별도 최저 보증금은 두지 않는다. |

### 11.2 연체료

| ID | 확정 규칙 |
| --- | --- |
| LATE-01 | 연체료는 시간 단위나 경과 24시간 올림 대신 **달력 날짜 차이**로 계산한다. |
| LATE-02 | 반납 예정일과 실제 반납일이 같으면, 약속 시각을 넘겼더라도 연체료는 0일분이다. 약속 시각 준수 여부와 연체료 과금은 구분한다. |
| LATE-03 | 반납 예정일의 다음 날 반납하면 1일분, 이틀 뒤 반납하면 2일분의 일일 대여료를 연체료로 계산한다. |
| LATE-04 | 공급자가 늦게 확인한 날짜가 아니라, 10장의 절차로 확정한 **실제 반납일**을 사용한다. |
| LATE-05 | 연체료의 미결제·금액 이의가 있으면 기본 대여료는 반납 확인 시 정산하고 보증금 반환을 보류한다. 임의의 자동 인출·자동 차감을 하지 않는다. |

```text
연체 일수 = 최대(0, 실제 반납일 - 반납 예정일)
연체료 = 일일 대여료 × 연체 일수
```

예: 반납 예정일이 2026-11-25인 경우

| 실제 반납일 | 연체 일수 | 연체료 |
| --- | --- | --- |
| 2026-11-25 | 0일 | 없음 |
| 2026-11-26 | 1일 | 일일 대여료 × 1 |
| 2026-11-27 | 2일 | 일일 대여료 × 2 |

**변경 기록:** 앞서 선택했던 경과 24시간 단위 올림과 시간 기준 유예·계산 방식은 이후 선택한 달력 날짜 기준으로 대체되었다. 기본 대여료의 24시간 기준은 변경하지 않았다. 달력 날짜를 산정할 서비스 공통 시간대는 추가 명세가 필요하다.

- 달력 날짜 계산에 사용할 서비스 공통 시간대와 경계 시각 처리.
- 대여 시작까지 12시간이 남지 않은 신청, 1시간 결제 대기가 대여 시작을 넘는 경우의 처리.
- AI 최종 모델·평가 데이터·품목별 목표 성능·운영 임계값.

## 18. 핵심 흐름 요약

```text
물품 등록
  기본 정보 → 사진 촬영 ↔ 대여 조건
  사진 미완료 상태에서도 대여 조건 이동 가능
  최종 게시 시 필수 사진 촬영·전체 확인 완료 여부 검사

예약
  대여 신청 → 공급자 승인 → 테스트 결제 → 예약 확정
  ├─ 공급자 미응답 12시간: 신청 만료
  └─ 승인 후 미결제 1시간: 승인 만료·일정 해제

이용·반납
  대여 전 상태 기록 → 물품 전달·이용 → 반납 사진 촬영·요청
  → 품질·동일 면·정렬 확인 → 손상 후보 또는 비교 보류
  → 공급자 반납 확인 / 이의 없는 24시간 경과
  → 거래 완료·기본 대여료 정산·보증금 반환
     단, 손상 신고·연체료 미결제·금액 이의가 있으면 보증금 반환 보류

후기
  거래 완료 → 7일 내 상호 후기 작성
  → 양쪽 작성 완료 또는 완료 후 7일 경과 시 공개·별점 집계
```
